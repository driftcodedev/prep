This folder is the Long Term tab of the prep site. Everything for the long-term plan (code, words, numbers, styles and tests) lives here. Read this whole page before changing anything.

## Rules

1. **Change files only inside `long-term/`.** Another chat works on the Short Term plan in the same repo. If you need a change outside this folder (the tab bar, the lock, the "The long-term plan" heading at the top of the tab, or anything in the Short Term plan), stop and ask Brett.
2. Add as many files and subfolders under `long-term/` as you need, for example `long-term/js/` or `long-term/data/foods.js`. Use relative imports (`./data/foods.js`).
3. Keep the `mount(root, context)` and `unmount(root)` exports in `app.js`. The page frame calls them.
4. Keep facts, amounts, prices and links in `data/`, and the code that draws them in `app.js` (and any modules it imports), the way the Short Term plan splits `data.js` from the rest.

## How the tab works

- Clicking Long Term shows a password form. `shell/tabs.js` owns that form.
- After the right password, the frame imports `long-term/app.js` and calls `mount(root, context)`. `root` is the empty `<div id="lt-root">`. Nothing in this folder downloads before the password is entered.
- `mount` may be `async`; the frame waits for it. Afterwards the frame moves focus to the first `h1`–`h3` inside the plan.
- The tab locks again when someone switches to Short Term, presses **Lock this tab**, or reloads the page. The frame then calls `unmount(root)` and empties `#lt-root`.
- Each unlock calls `mount` again, so draw from scratch every time. The browser keeps the module loaded between unlocks, so reset any module-level variables inside `mount`. Stop timers and remove `window`/`document` listeners in `unmount`.
- The tab already has an `h1` ("The long-term plan") above your content, so start your headings at `h2`.
- `app.js` loads `style.css` from this folder the first time the plan opens.
- The **README** and **Lock this tab** buttons above your content belong to the frame, not to this folder. The README's pages are in `shell/readme-pages.js`; if they need changing, ask Brett.

### The household from the Short Term tab

`context.household` is the household the person entered on the Short Term tab, or `null` if they haven't entered anyone. Treat it as read-only, and never write to the `prep-household-v1` localStorage key it comes from. Its shape:

```js
{
  months: 6, reserve: 20, store: "costco",       // or "walmart"
  hasScale: false, hasLighters: false, ...,      // gear they already own
  people: [{
    id, name, sex,                               // sex: "male" | "female"
    age, months,                                 // strings as typed; age "0" means a baby, months gives the age
    ft, inch, weight,                            // strings as typed (feet, inches, pounds)
    activity,                                    // "sedentary" | "light" | "moderate" | "heavy"
    feeding,                                     // babies: "formula" | "breast" | "both"
    keepWeight,                                  // true = hold current weight instead of losing to a healthy BMI
    flags: { pregnant, breastfeeding, peanut, diabetes, kidney, celiac }
  }]
}
```

Values from the form are strings. Convert them before doing math.

### Reusing the Short Term math

You may import, read-only, from `../short-term/js/calc.js` (for example `planHousehold`, `planPerson`, `cupsText`) and `../short-term/js/data.js`. Don't edit those files. Cover anything you import with a test in `long-term/test/`, so you find out if the Short Term side changes. Never import `../short-term/js/app.js`: it runs the Short Term page as soon as it loads.

`planHousehold` and `planPerson` expect numbers (`heightIn`, `weightLb`, `age` in years), not the form's strings. `toPerson()` in `short-term/js/app.js` shows the conversion; copy it into `long-term/` rather than importing it.

## The Cobscook Bay map

The tab is a map of everything within 10 miles of Cobscook Bay: 1-mile distance rings you can turn on
and off (each picked distance gets its own color), town labels with populations, names for the parts
of the bay, and every house for sale with its power setup.

- **Houses** live in `data/houses.js`. The header explains each field. To refresh them: list the
  current single-family listings per town on century21.com (it shows the Maine MLS feed), then take
  each house's map point, list date and power fields from its compass.com page. Houses with no map
  point get an `approx` note and a pin at the village or road. Keep `power: "offgrid-solar"` for
  houses whose MLS record says off grid with solar; don't guess.
- **Weekly check:** a scheduled task refreshes `data/houses.js` every Sunday evening (Eastern). It
  removes houses that sold or whose listing was withdrawn or expired (an off-grid solar house that
  expired unsold stays, as `"expired"`), adds new listings within 10 miles, updates `HOUSES_CHECKED`,
  and records what changed in `HOUSES_CHANGES`, which shows as a line under the map. Listings from the
  last 14 days get a New badge (`isNew` in `js/geo.js`). The task commits only `long-term/`.
- **Rings** come from `tools/build_geo.py`, which needs `pip install basemap basemap-data-hires shapely pyproj`.
  It measures straight-line distance from the bay's shore in UTM 19N and writes `data/geo.json`. Each
  ring is a full closed band over land and water (`geometry`, drawn on the live map), with a land-only
  copy (`land`, `landSqmi`) that the paper map draws stronger, so the coast shows without a base map.
- **Zoom:** the map zooms out only as far as the whole 10-mile ring, worked out from the map's size
  (again after full screen or the resize handle), and can't be panned far past it.
- **Leaflet** loads only after the password (app.js imports it inside `mount`). Its CSS is scoped to
  `#lt-root` so it can't touch the Short Term tab.
- Map tiles come from OpenStreetMap (map) and Esri (satellite, terrain, and the photo in each popup).
  CARTO's free tiles, used before, started showing "API KEY REQUIRED" in Nov 2026. They
  need a connection; the rings, pins and labels are drawn from this folder.

### Tidal currents and flats

The **Tidal currents** control above the map has three modes (Off, Strongest, By hour of the tide)
and a **Flats that dry at low tide** checkbox. Nothing loads until one is used.

- **Source:** NOAA's WebGNOME location file for Passamaquoddy Bay, ME, built on the Bedford
  Institute of Oceanography's QUODDY model: 12 current snapshots through one average tide on a
  triangle grid about 100–200 m apart, with ground that floods and dries. To refresh: on
  gnome.orr.noaa.gov open Location Files → Passamaquoddy Bay, run the wizard (any spill), then
  Save → "Download Your Model Setup". Put the .gnome file in `tools/source/` and run
  `python3 tools/build_currents.py` from `long-term/` (needs netCDF4, numpy, matplotlib, pillow).
- **Check:** the model's peak at Estes Head, Eastport is 2.3 knots; NOAA's current table gives
  2.2 on the flood and 2.4 on the ebb. South of 44.83° N the grid turns coarse near the model's
  open edge, so it's cropped there.
- **Strongest:** `currents-peak.png`, the strongest current on an average tide in five bands
  (under 0.5, 0.5–1, 1–2, 2–3, over 3 knots), drawn in Web Mercator so it lines up with the map.
  The distance rings fade while the currents show, so their colors don't mix.
- **By hour of the tide:** arrows on a canvas (`createCurrents()` in `js/currents.js`), colored and
  sized by speed, with a slider, step buttons and Play. Hours are counted from high or low tide at
  Eastport (`tideLabel()`), so they work with an Eastport tide table. Points come in three
  spacings (1.6 km, 800 m, 400 m) that appear as you zoom in.
- **Flats:** `currents-flats.png`, ground that is dry at the low-tide snapshot but covered at high
  tide.
- **Tap the water:** the popup adds the current at the chosen hour, the strongest current there,
  when it slackens, and whether the spot dries.
- **Paper copy:** the map part has a "Tidal currents and flats" section with
  `currents-print.png` and a table of places (`CURRENTS.reportAreas` in `data/plan.js`) with typical
  and fastest current and slack times. Those numbers are worked out at full grid resolution by the
  build tool (`areas` in currents.json).
- Words for the control and the report are in `CURRENTS` in `data/plan.js`.

## The Fishing view

The tab opens on a **Map / Fishing** switch (`render()` in `app.js`). The last view picked is kept
in `localStorage` (`prep-lt-view`). The map's Leaflet code loads only the first time the Map view
is shown, so opening straight to Fishing doesn't download it.

- **Numbers:** `data/fishing.js`, written by `python3 tools/fishing_model.py` (run from
  `long-term/`). Don't edit it by hand. Every number is the whole amount in the bay in that season,
  before anyone fishes: no cutoffs and no fishing method yet. The method, checks and sources are in
  Brett's "Cobscook fishing data: sources check" doc (Nov 26–27, 2026). Six two-month seasons; for
  each species: `lb` (pounds in the bay, live weight; scallops are meat), `kcal` (calories in the
  meat), `meatShare`, `kcalPerLb`, `confidence` (1–5) and `source`. `null` means not counted:
  species with no count in the bay are kept with no numbers rather than guessed. For species that
  stay all year, each season assumes nothing was taken earlier, so their seasons must never be
  added together. `HERRING_CATCH` holds the bay's 1947–58 herring catches, which set herring's
  seasons. Active adults fed a year = calories ÷ 3,000 a day ÷ 365.
- **Words:** `data/fishing-notes.js` holds the page text, the 1–5 confidence scale, species notes
  (size, gear, rules, safety), one color per species, the herring methods, the method and the sources.
- **The view** (`js/fishing.js`) is one table: a row per species, a column per season. Tapping a
  season header sorts the rows by that season, most to least (then none counted, not counted that
  season, and no count). "Show" picks calories or pounds. "Numbers" picks amounts, "% of season"
  (each species' share of that season's total, by column) or "% of best season" (each season as a
  % of the species' own best season, by row; seasons are never added up). Tapping a species opens
  its notes in a row under it. Show and Numbers are kept in `localStorage` (`prep-lt-fish`); the
  season starts on today's.
- **Parked until fishing methods are picked:** cutoffs, catch per hour, cleaning time and the 2025
  scallop drop. The old per-trip numbers are gone (they're in git history before Nov 27, 2026).

## Paper copy: Print the full report / Download PDF

The same two buttons as the Short Term tab sit under the Map / Fishing switch and at the bottom of
the tab (the bottom one in a `.report-foot` with "Keep a paper copy"). Both give everything on the
tab, whichever view is open: a cover with contents, then each part on new pages: Why Cobscook Bay,
the map (with tidal currents and flats), houses for sale, Solar panels, Off-grid checklist,
fishing by season, Nov–Dec food shortage, Species extinction and Pumping gas out of a car. About 37
letter pages.

- **One content list:** `buildReport()` in `js/report.js` returns plain blocks (headings,
  paragraphs, tables, pictures, house cards). Change what's in the report there, and both outputs
  follow. It's pure, so `test/report.test.js` runs it in Node.
- **README pages** in the report are the ones in `README_IN_REPORT`, read from the JSON the site
  publishes in `index.html` (`#rmpages`), so they match the README button. Pages about using the
  website stay out. Edits a reader makes in their own browser aren't printed.
- **Pictures** are plain SVG, drawn so both the browser and pdfmake can print them: `mapSvg()` (the
  rings, bay, towns and every house from `data/geo.json`, with numbers that match the house list)
  and `ringSvg()` (each season's calories as a ring, drawn as filled arcs, not CSS).
- **Print the full report:** `reportHtml()` fills the hidden `.lt-print` box. In print, only that
  box shows (`#lt-root.lt-has-print`), the tab's masthead is hidden, and pages are numbered by an
  `@page ltreport` rule that only applies to the box. The box is also filled a moment after the tab
  opens, so the browser's own Print (Ctrl+P) gives the same report.
- **Download PDF:** `reportPdf()` in `js/report-pdf.js` turns the blocks into a pdfmake document
  that looks like the Short Term PDF (Roboto, thin table rules, a new page per part, page numbers).
  pdfmake loads only when the button is pressed. Roboto has no ⅓ or ⅔, so they're written out.
- A heading and a short table after it (26 rows or fewer) are kept on the same page.

## Look and wording

- Reuse the site's look, which is already loaded from `short-term/css/style.css`. `style.css` in this folder lists the colors (`var(--lid)`, `var(--bean)` and so on), fonts and classes (`.section-title`, `.muted`, `.btn`, `.field`, `.data` tables).
- Escape any text you put into HTML. `app.js` has `esc()` for this.
- Make it work on a phone first. Check it at 390 px wide.

## Brett's preferences

- Plain, short wording with no jargon, in sentence case.
- Amounts in cups and spoons people can measure, not grams.
- For products, cheap options first. Pick items with lots of ratings and a low share of 1-star reviews; around 10% one-star is a red flag. Give the price, the link, and the date prices were checked.
- Ask before big changes, or before adding things he didn't ask for.

## Try it locally

ES modules don't load from `file://`, so serve the folder:

```
git clone https://github.com/driftcodedev/prep.git
cd prep
python3 -m http.server 8765
```

Open http://localhost:8765/, click Long Term and enter the password.

Run the tests with Node 20 or newer:

```
npm test            # both plans
npm run test:long   # just this folder
```

## Publish

```
git pull --rebase origin main     # pick up the other chat's Short Term changes first
npm test
git add long-term/
git commit -m "Long term: <what changed>"
git push origin main
```

Stage only `long-term/` so you never commit someone else's work by accident. Then wait a minute or two, open https://driftcodedev.github.io/prep/#long-term, refresh, unlock, and check your change is there.
